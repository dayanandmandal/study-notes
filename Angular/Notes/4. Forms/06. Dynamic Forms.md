# Dynamic Forms

## What It Is

Dynamic forms are generated from metadata/config instead of hardcoded templates.

Use when form fields vary by user role, product type, or backend-driven schema.

---

## Typical Metadata Model

```ts
type FieldConfig = {
  key: string;
  label: string;
  type: 'text' | 'email' | 'number';
  required?: boolean;
};
```

Example config:

```ts
const fields: FieldConfig[] = [
  { key: 'name', label: 'Name', type: 'text', required: true },
  { key: 'email', label: 'Email', type: 'email', required: true }
];
```

---

## Build FormGroup From Config

```ts
buildForm(fields: FieldConfig[]): FormGroup {
  const group: Record<string, FormControl> = {};

  for (const field of fields) {
    group[field.key] = new FormControl('', field.required ? [Validators.required] : []);
  }

  return new FormGroup(group);
}
```

---

## Render Fields In Template

```html
<form [formGroup]="form" (ngSubmit)="submit()">
  <ng-container *ngFor="let field of fields">
    <label>{{ field.label }}</label>
    <input [type]="field.type" [formControlName]="field.key" />
  </ng-container>

  <button type="submit">Save</button>
</form>
```

---

## Architecture Tips (Senior Level)

- keep field config schema versioned if backend-driven
- separate renderer components by field type for maintainability
- centralize validation mapping from config to Angular validators
- protect against invalid/untrusted remote schema

---

## Common Mistakes

- putting all rendering logic in one giant template
- no typed abstraction for config, causing runtime errors
- mixing transport schema and UI schema without translation layer

---

## Interview Quick Lines

- Dynamic forms trade simplicity for flexibility.
- They are powerful in enterprise products with frequently changing workflows.
- Strong schema design and renderer composition are key to maintainability.
