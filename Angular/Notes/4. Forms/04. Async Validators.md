# Async Validators

## What It Is

Async validators run asynchronous checks, usually server-side validation.

Typical use case: username or email uniqueness.

---

## Async Validator Function

```ts
import { AbstractControl, AsyncValidatorFn, ValidationErrors } from '@angular/forms';
import { map, catchError, of, debounceTime, switchMap, first } from 'rxjs';

export function usernameAvailableValidator(api: UserApiService): AsyncValidatorFn {
  return (control: AbstractControl) => {
    return of(control.value).pipe(
      debounceTime(300),
      switchMap((value) => api.checkUsername(value)),
      map((exists) => (exists ? { usernameTaken: true } : null)),
      catchError(() => of(null)),
      first()
    );
  };
}
```

Apply on control:

```ts
username: this.fb.control('', {
  validators: [Validators.required],
  asyncValidators: [usernameAvailableValidator(this.userApi)],
  updateOn: 'blur'
})
```

---

## Why `updateOn: 'blur'`

It prevents firing API checks on every keystroke and reduces backend load.


---

## Common Mistakes

- forgetting to complete observable
- triggering API requests too frequently
- treating network error as validation failure instead of graceful fallback

---

## Interview Quick Lines

- Async validators are for IO-bound rules.
- Use `switchMap` to cancel stale requests.
- `updateOn: 'blur'` is a practical optimization in most forms.
