# Query Parameters

## What Are Query Parameters

Query parameters store optional view state in URL.

Examples:

- `/users?page=2`
- `/products?sort=price&order=asc`

They are ideal for filter, sort, pagination, tabs, search terms.

---

## Navigate With Query Params

```ts
this.router.navigate(['/users'], {
  queryParams: { page: 2, sort: 'name', active: true }
});
```

---

## Read Query Params

```ts
this.route.queryParamMap.subscribe((qp) => {
  const page = Number(qp.get('page') ?? 1);
  const sort = qp.get('sort') ?? 'name';
});
```

Use defaults and type conversion.

---

## Preserve or Merge Existing Query Params

```ts
this.router.navigate([], {
  relativeTo: this.route,
  queryParams: { page: 3 },
  queryParamsHandling: 'merge'
});
```

- `merge`: update specific keys while keeping others.
- `preserve`: keep current params as-is.

### Detailed Behavior (Replace vs Merge vs Preserve)

Assume current URL is:

```txt
/users?page=2&sort=name&active=true
```

And navigation call uses:

```ts
queryParams: { page: 3 }
```

| Strategy | Navigation Example | Result URL | What Happens |
| --- | --- | --- | --- |
| replace (default) | `this.router.navigate(['/users'], { queryParams: { page: 3 } })` | `/users?page=3` | Existing params are replaced completely |
| merge | `this.router.navigate(['/users'], { queryParams: { page: 3 }, queryParamsHandling: 'merge' })` | `/users?page=3&sort=name&active=true` | Existing params are kept, conflicting keys are overwritten by new values |
| preserve | `this.router.navigate(['/users'], { queryParams: { page: 3 }, queryParamsHandling: 'preserve' })` | `/users?page=2&sort=name&active=true` | Current params are kept exactly, new queryParams object is ignored |

### Key Rules

- In `merge`, new value wins when key already exists.
- In `preserve`, current URL query params win.
- If you do not set `queryParamsHandling`, Angular uses default replace behavior.

### Remove One Query Param While Keeping Others

```ts
this.router.navigate([], {
  relativeTo: this.route,
  queryParams: { sort: null },
  queryParamsHandling: 'merge'
});
```

Typical result: `sort` is removed, other query params stay.

### Most Common Real-World Pattern (Filter Screens)

```ts
this.router.navigate([], {
  relativeTo: this.route,
  queryParams: { page: 1, sort: selectedSort },
  queryParamsHandling: 'merge'
});
```

Use this when one control changes and you want to keep other filters in URL.

## Common Mistakes

- storing critical identity in query params instead of route params
- forgetting to merge existing params and accidentally dropping filters
- not sanitizing user-provided query values

---

## 5 Years Interview Quick Lines

- Query params represent optional UI state, not primary resource identity.
- They should be bookmarkable and restorable.
- Good URL state design improves UX and debugging.
