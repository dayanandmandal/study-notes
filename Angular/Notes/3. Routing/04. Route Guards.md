# Route Guards

## Why Route Guards Exist

Guards control whether navigation can proceed.

They protect routes, prevent data loss, and gate feature access.

Guard return types:

- `boolean`
- `UrlTree`
- `Observable<boolean | UrlTree>`
- `Promise<boolean | UrlTree>`

Returning `UrlTree` is preferred over manual `navigate` in many cases because router handles redirection declaratively.

---

## CanActivate

Checks if route can be activated after route match.

```ts
import { CanActivateFn, Router } from '@angular/router';
import { inject } from '@angular/core';
import { AuthService } from './auth.service';

export const authGuard: CanActivateFn = () => {
  const auth = inject(AuthService);
  const router = inject(Router);
  return auth.isLoggedIn() ? true : router.createUrlTree(['/login']);
};
```

Use for authentication and permission checks.

---

## CanDeactivate

Checks if user can leave current route.

```ts
import { CanDeactivateFn } from '@angular/router';

export interface CanLeave {
  hasUnsavedChanges(): boolean;
}

export const pendingChangesGuard: CanDeactivateFn<CanLeave> = (component) => {
  return component.hasUnsavedChanges()
    ? confirm('You have unsaved changes. Leave page?')
    : true;
};
```

Use for unsaved forms, in-progress workflows.

---

## CanMatch

Controls if a route should be considered a match.

```ts
import { CanMatchFn, Route, UrlSegment } from '@angular/router';
import { inject } from '@angular/core';
import { FeatureService } from './feature.service';

export const adminMatchGuard: CanMatchFn = (_route: Route, _segments: UrlSegment[]) => {
  const feature = inject(FeatureService);
  return feature.isAdminEnabled();
};
```

Route usage:

```ts
{ path: 'admin', canMatch: [adminMatchGuard], loadChildren: () => import('./admin/admin.routes').then(m => m.ADMIN_ROUTES) }
```

Use for role/flag based route selection before activation/loading flow.

---

## CanActivate vs CanMatch

- CanActivate: route already matched, now authorize activation.
- CanMatch: decide if route can match at all.

Senior interview point: CanMatch is useful to select alternate route configs for same path based on runtime conditions.

---

## Common Mistakes

- putting heavy API logic in every guard causing navigation delays
- mixing side effects in guards instead of returning clear boolean/UrlTree
- using CanActivate where CanMatch gives cleaner route branching

---

## 5 Years Interview Quick Lines

- Keep guards fast and deterministic.
- Prefer UrlTree returns for redirect logic.
- Use CanDeactivate for data-loss prevention.
- Use CanMatch for feature gating and route-level branching.
