# Route Parameters

## What Are Route Parameters

Route parameters are dynamic path segments used to identify specific resources.

Example:

```ts
{ path: 'users/:id', component: UserDetailsComponent }
```

- `:id` is a route parameter.
- URL like `/users/42` maps `id = 42`.

---

## Navigating With Route Params

```ts
this.router.navigate(['/users', userId]);
```

Prefer array syntax for safe path segment construction.

---

## Reading Route Params

### Snapshot (One-time read)

```ts
const id = this.route.snapshot.paramMap.get('id');
```

Using `params` object style:

```ts
const id = this.route.snapshot.params['id'];
```

Use when component is recreated and value is needed once.

### Reactive (Observe changes)

```ts
this.route.paramMap.subscribe((params) => {
  const id = params.get('id');
});
```

Using `params` object style:

```ts
this.route.params.subscribe((params) => {
  const id = params['id'];
});
```

Use when same component instance can stay alive while param changes.

---

## ParamMap vs params

- `paramMap` offers `get('key')` API and better null-safety.
- `params` is plain object style.

Both are valid. Prefer `paramMap` in interview answers because it is explicit and safer when values can be missing.

Interview best practice: prefer `paramMap`.

---

## Common Mistakes

- using snapshot where param can change in reused route
- not validating/normalizing param type (string to number)
- making API calls without handling null/invalid id

---

## 5 Years Interview Quick Lines

- Route params represent resource identity.
- They are part of URL path and affect route matching.
- Use `paramMap` with reactive handling for robust component reuse.

---

## Quick Q&A

Q: Route param vs query param?
A: Route param is part of path (`/users/42`), query param is optional metadata (`/users?page=2`).

Q: Why subscribe to paramMap?
A: Because the same component can be reused when only params change.
