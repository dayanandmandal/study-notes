# Preloading Strategies

## What Is Preloading

Preloading loads lazy modules in background after app startup, so future navigation is faster.

It is a trade-off between network usage and route transition speed.

---

## Built-In Strategy: PreloadAllModules

```ts
import { provideRouter, withPreloading, PreloadAllModules } from '@angular/router';

provideRouter(routes, withPreloading(PreloadAllModules));
```

Pros:

- faster second-route navigation
- simple to enable

Cons:

- higher network usage after initial load
- may preload low-value features unnecessarily

---

## Custom Selective Preloading

Preload only routes marked by metadata.

```ts
import { Injectable } from '@angular/core';
import { PreloadingStrategy, Route } from '@angular/router';
import { Observable, of } from 'rxjs';

@Injectable({ providedIn: 'root' })
export class SelectivePreloadStrategy implements PreloadingStrategy {
  preload(route: Route, load: () => Observable<unknown>): Observable<unknown> {
    return route.data?.['preload'] ? load() : of(null);
  }
}
```

Route config:

```ts
{ path: 'reports', data: { preload: true }, loadChildren: () => import('./reports/reports.routes').then(m => m.REPORT_ROUTES) }
```

---

## How to Choose Strategy

Use `PreloadAllModules` when:

- app has moderate route count
- users frequently navigate across many features

Use selective preloading when:

- app is large with many rarely-used features
- bandwidth sensitivity is important
- user journeys are predictable

---

## Common Mistakes

- preloading everything in bandwidth-constrained environments
- no route priority strategy for business-critical paths
- assuming preloading helps first paint (it does not)

---

## 5 Years Interview Quick Lines

- Preloading improves later navigation, not initial render.
- It should be driven by user flow analytics.
- Selective strategy often gives better real-world trade-off than preload-all.
