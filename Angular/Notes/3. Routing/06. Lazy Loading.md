# Lazy Loading

## What Is Lazy Loading

Lazy loading means feature code is downloaded only when user navigates to that route.

It reduces initial bundle size and improves first load performance.

---

## Route-Level Lazy Loading

```ts
{ path: 'orders', loadChildren: () => import('./orders/orders.routes').then(m => m.ORDERS_ROUTES) }
```

Angular loads this chunk when `/orders` is visited.

---

## Why It Matters in Large Apps

- better startup time
- lower initial JavaScript parse/execute cost
- clearer feature boundaries in architecture

---

## Interview Architecture Angle

Good lazy-loading design is feature-driven:

- each business domain as isolated route boundary
- keep truly shared code in shared/core layer
- avoid cross-feature tight coupling

---

## Lazy Loading and Guards

Combine with `CanMatch` to avoid loading/activating gated feature paths unnecessarily.

---

## Common Mistakes

- lazy loading tiny utilities instead of feature modules/routes
- importing lazy feature dependencies into eagerly loaded root path
- circular dependencies between lazy features and shared layers

---

## 5 Years Interview Quick Lines

- Lazy loading is not only performance optimization; it is also an architecture boundary.
- Route-level split should align with user journeys and business domains.
- Measure with bundle analysis and route navigation timings.
