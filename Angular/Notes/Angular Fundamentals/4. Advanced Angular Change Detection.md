# Angular Change Detection - Mental Models & Interview Notes

## Default Change Detection Strategy

```ts
@Component({
  changeDetection: ChangeDetectionStrategy.Default
})
```

**Think of it as:**

```txt
"Check me whenever Angular runs Change Detection."
```

Characteristics:

- Angular checks the component during every CD cycle.
- Mutating objects and arrays usually updates the UI.
- Easier to work with but less optimized.

---

## OnPush Change Detection Strategy

```ts
@Component({
  changeDetection: ChangeDetectionStrategy.OnPush
})
```

**Think of it as:**

```txt
"Only check me when something important happens."
```

Triggers:

- @Input reference changes
- Event inside the component
- Observable emits through async pipe
- markForCheck()
- detectChanges()

Benefits:

- Better performance
- Fewer unnecessary checks
- Ideal for large applications

---

# ChangeDetectorRef

```ts
constructor(private cd: ChangeDetectorRef) {}
```

Used to manually control Change Detection.

---

## detectChanges()

```ts
this.cd.detectChanges();
```

**Think of it as:**

```txt
"Check this component right now."
```

Characteristics:

- Runs CD immediately.
- Checks current component and its subtree.
- Does not wait for the next CD cycle.

Common Use Cases:

- Third-party library callbacks
- Manual DOM updates
- External events Angular doesn't know about

---

## markForCheck()

```ts
this.cd.markForCheck();
```

**Think of it as:**

```txt
"This component should be checked during the next CD cycle."
```

Characteristics:

- Does not run CD immediately.
- Marks component as dirty.
- Mainly useful with OnPush components.

Common Use Cases:

- Updating data from external sources
- Async callbacks
- Mutating existing objects in OnPush components

---

## detach()

```ts
this.cd.detach();
```

**Think of it as:**

```txt
"Ignore this component completely."
```

Characteristics:

- Removes component from Angular's CD tree.
- Angular stops checking it.

Common Use Cases:

- Real-time dashboards
- Large tables
- Charts updating frequently

---

## reattach()

```ts
this.cd.reattach();
```

**Think of it as:**

```txt
"Start checking this component again."
```

Characteristics:

- Adds component back into Angular's CD tree.
- Angular resumes checking it normally.

---

# NgZone

```ts
constructor(private ngZone: NgZone) {}
```

Used to control whether Angular should run Change Detection.

---

## runOutsideAngular()

```ts
this.ngZone.runOutsideAngular(() => {
  window.addEventListener("mousemove", () => {
    // no Angular CD
  });
});
```

**Think of it as:**

```txt
"Run this code, but don't trigger Change Detection."
```

Common Use Cases:

- Mouse tracking
- Drag & drop
- Canvas rendering
- Charts
- Games

Benefits:

- Prevents excessive CD cycles
- Improves performance

---

## run()

```ts
this.ngZone.run(() => {
  this.counter++;
});
```

**Think of it as:**

```txt
"I'm back inside Angular. Change Detection can run again."
```

Common Use Cases:

- After runOutsideAngular()
- Updating UI state

---

# Async Pipe

```html
{{ user$ | async }}
```

**Think of it as:**

```txt
"Angular manages subscribe, unsubscribe and UI updates for me."
```

Benefits:

- Auto subscribe
- Auto unsubscribe
- Works perfectly with OnPush
- Cleaner templates

---

# Pipes

## Pure Pipe (Default)

```ts
@Pipe({
  name: 'fullName',
  pure: true
})
```

**Think of it as:**

```txt
"Recalculate only when inputs actually change."
```

Benefits:

- Better performance
- Recommended for most cases

---

## Impure Pipe

```ts
@Pipe({
  name: 'custom',
  pure: false
})
```

**Think of it as:**

```txt
"Recalculate every time Angular checks."
```

Characteristics:

- Runs every CD cycle
- Can become expensive
- Use sparingly

---

# trackBy

```html
<div *ngFor="let item of items; trackBy: trackById"></div>
```

```ts
trackById(index: number, item: User) {
  return item.id;
}
```

**Think of it as:**

```txt
"Reuse existing DOM elements whenever possible."
```

Without trackBy:

```txt
Angular may recreate DOM elements unnecessarily.
```

With trackBy:

```txt
Angular identifies items by ID and reuses DOM nodes.
```

Benefits:

- Better performance
- Essential for large tables and lists

---

# Signals (Angular 16+)

```ts
count = signal(0);
```

Update:

```ts
this.count.set(10);
```

Read:

```html
{{ count() }}
```

**Think of it as:**

```txt
"Angular already knows exactly what changed."
```

Benefits:

- Fine-grained reactivity
- Less Change Detection work
- Better performance
- Modern Angular direction
