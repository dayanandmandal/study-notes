# Senior-Level Interview Notes

## What Actually Gets Cancelled in switchMap?

Many developers say:

```text
switchMap cancels the previous request
```

More accurate:

```text
switchMap unsubscribes from the previous inner Observable
```

If the inner Observable is an Angular HTTP request, the browser request is typically aborted as well.

Interviewers often expect this distinction.

---

## mergeMap and Race Conditions

Question:

```text
Why not use mergeMap everywhere?
```

Example:

```text
Update User Name
Update User Email
Update User Address
```

Using mergeMap:

```text
Request #3 may finish before Request #1
```

Completion order is not guaranteed.

Important point:

```text
mergeMap can introduce race conditions.
```

---

## concatMap Preserves Order

Guarantee:

```text
Requests execute sequentially.
```

Example:

```text
Save Step 1
Save Step 2
Save Step 3
```

Execution:

```text
Step 1 completes
Step 2 completes
Step 3 completes
```

Use when operation order matters.

---

## exhaustMap Prevents Duplicate Actions

Common interview question:

```text
User clicks Login button 5 times.
Which operator should be used?
```

Answer:

```text
exhaustMap
```

Behavior:

```text
First click starts request

All additional clicks are ignored

Until the first request completes
```

Typical use cases:

- Login
- Form submission
- Payment processing

---

## Most Common Operator in Angular

Usually:

```text
switchMap
```

Common scenarios:

- Route parameter changes
- Search box
- Typeahead
- Form valueChanges
- Dependent API calls

Example:

```ts
this.route.params.pipe(
  switchMap((params) => this.userService.getUser(params.id)),
);
```

## Subscription Management

Question:

```text
Do higher-order mapping operators manage inner subscriptions automatically?
```

Answer:

```text
Yes.
```

Operators:

- switchMap
- mergeMap
- concatMap
- exhaustMap

automatically subscribe and unsubscribe from inner Observables.

This is one reason they are preferred over manual nested subscriptions.

---

## Nested Subscribe Anti-Pattern

Avoid:

```ts
this.route.params.subscribe(params => {
  this.http.get(...).subscribe(res => {
    ...
  });
});
```

Problems:

- Harder to read
- Harder to manage errors
- Harder to manage subscriptions

Preferred:

```ts
this.route.params.pipe(
  switchMap(params => this.http.get(...))
);
```

# Senior-Level Quick Summary

```text
switchMap
→ Latest wins
→ Previous inner Observable unsubscribed
→ Best for search, routing, dependent requests

mergeMap
→ Everything runs
→ Concurrent execution
→ Can cause race conditions

concatMap
→ Sequential execution
→ Preserves order

exhaustMap
→ Ignore new emissions while busy
→ Best for login, submit, payment flows
```
