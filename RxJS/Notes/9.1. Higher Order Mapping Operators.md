# Higher Order Mapping Operators

## Why Do They Exist?

Sometimes an Observable emits another Observable.

Example:

```ts
searchText$.pipe(
  map(text => http.get(`/search?q=${text}`))
)
```

Result:

```ts
Observable<Observable<Response>>
```

Higher Order Mapping Operators flatten the inner Observable and control what happens when multiple inner Observables are created.

---

## switchMap()

Rule:

```text
Cancel previous, keep latest
```

Use for:

* Search
* Autocomplete
* Typeahead

Example:

```text
a → HTTP
ab → HTTP
abc → HTTP
```

Result:

```text
Cancel a
Cancel ab
Keep abc
```

---

## mergeMap()

Rule:

```text
Run all concurrently
```

Use for:

* Multiple independent API calls
* Parallel processing

Result:

```text
a → HTTP
ab → HTTP
abc → HTTP
```

All requests continue running.

---

## concatMap()

Rule:

```text
Queue requests
Run one at a time
```

Use for:

* Save operations
* Ordered processing

Result:

```text
Run a
Then ab
Then abc
```

Order is preserved.

---

## exhaustMap()

Rule:

```text
Ignore new values while busy
```

Use for:

* Login button
* Submit button
* Payment requests

Result:

```text
Click #1 → Process

Click #2 → Ignore
Click #3 → Ignore
```

Until the first request completes.

---

# Quick Comparison

| Operator   | Behavior        |
| ---------- | --------------- |
| switchMap  | Cancel previous |
| mergeMap   | Run all         |
| concatMap  | Queue           |
| exhaustMap | Ignore new      |

---

# Easy Memory Trick

```text
switchMap = Latest wins

mergeMap = Everyone runs

concatMap = Wait your turn

exhaustMap = Already busy
```
