# Angular 14 Unsubscribe Handling

## 1. AsyncPipe (The Gold Standard)

In Angular 14, the `AsyncPipe` remains the absolute best practice for rendering stream data directly to the DOM.

### Mechanism

- Subscribes to an `Observable` or `Promise` directly from the HTML template.
- Automatically triggers change detection, aligning perfectly with `ChangeDetectionStrategy.OnPush`.
- Automatically **unsubscribes** when the component is destroyed.

### Senior-Level Implementation (Angular 14)

```typescript
import { Component } from '@angular/core';
import { Observable, interval } from 'rxjs';
import { map } from 'rxjs/operators';

@Component({
  selector: 'app-async-pipe',
  template: `
    <!-- 'as' syntax creates a single subscription and avoids duplicate stream execution -->
    <div *ngIf="data\$ | async as value; else loading">
      <p>Current Metric: {{ value }}</p>
    </div>
    <ng-template #loading>Awaiting data...</ng-template>
  `
})
export class AsyncPipeComponent {
  data\$: Observable<number> = interval(1000).pipe(map(v => v * 2));
}
```

### Architectural Trade-offs

- **Pros:** Complete elimination of manual lifecycle code. No risk of memory leaks.
- **Cons:** Data is scoped strictly to the view. If business logic in the TypeScript class requires the values, you must introduce side-effects (`tap`) or use component-class subscriptions.
- **Pitfalls:** Avoid repeating `{{ stream$ | async }}` multiple times for the same observable in a template. It spins up separate subscriptions, which can duplicate HTTP calls or background tasks. Use the `as` syntax instead.

## 2. takeUntil() (The Standard Angular 14 Declarative Pattern)

For streams that must be handled inside the TypeScript file (e.g., combining route parameters with API calls), `takeUntil` is the standard enterprise pattern for Angular 14.

### Mechanism

- Uses a private `Subject` notifier that emits once during `ngOnDestroy`.
- The `takeUntil` operator monitors this notifier and completes the stream instantly when an emission occurs.

### Senior-Level Implementation (Angular 14)

```typescript
import { Component, OnInit, OnDestroy } from '@angular/core';
import { Subject, interval } from 'rxjs';
import { takeUntil } from 'rxjs/operators';

@Component({
  selector: 'app-take-until',
  template: `<p>Data processing running...</p>`
})
export class TakeUntilComponent implements OnInit, OnDestroy {
  // Use void or boolean type safely
  private destroy\$ = new Subject<void>();

  ngOnInit(): void {
    interval(1000)
      .pipe(
        // Core business logic operators go here...
        takeUntil(this.destroy\$) // Crucial position
      )
      .subscribe({
        next: val => console.log('Data:', val),
        error: err => console.error(err)
      });
  }

  ngOnDestroy(): void {
    this.destroy\$.next();
    this.destroy\$.complete(); // Cleans up the subject stream itself
  }
}
```

### Architectural Trade-offs

- **Pros:** Declarative and highly compatible with complex RxJS pipe architectures.
- **Cons:** Introduces repetitive boilerplate across components (`destroy$` subject + `ngOnDestroy` lifecycle method).
- **The "Operator Order" Pitfall:** `takeUntil` must almost always be the **last operator** in your `pipe()` chain. If operators that spawn inner streams (like `switchMap`, `mergeMap`) or caching operators (like `shareReplay`) are placed _after_ `takeUntil`, those sub-streams can escape garbage collection and cause silent memory leaks.

## 3. Subscription.unsubscribe() (The Imperative/Manual Approach)

Manual subscription management should be used sparingly in Angular 14, typically reserved for non-component classes (like utility scripts or global event interceptors) where Angular lifecycles don't apply.

### Mechanism

- Manually assigns a `Subscription` instance and explicitly invokes `.unsubscribe()` to sever the observer path.

### Senior-Level Implementation (Angular 14)

Instead of storing multiple standalone subscription variables, use a single base `Subscription` and attach child subscriptions using `.add()`.

```typescript
import { Component, OnInit, OnDestroy } from "@angular/core";
import { Subscription, interval } from "rxjs";

@Component({
  selector: "app-manual",
  template: `<p>Manual tracking running...</p>`,
})
export class ManualComponent implements OnInit, OnDestroy {
  private subs = new Subscription();

  ngOnInit(): void {
    this.subs.add(interval(1000).subscribe((val) => console.log("A:", val)));
    this.subs.add(interval(2000).subscribe((val) => console.log("B:", val)));
  }

  ngOnDestroy(): void {
    // Single call unsubscribes all child subscriptions cleanly
    this.subs.unsubscribe();
  }
}
```

### Architectural Trade-offs

- **Pros:** Extremely explicit; easy for junior developers to reason about.
- **Cons:** Highly imperative. It forces clean-up logic outside of the reactive RxJS pipe pipeline.
- **Pitfalls:** High risk of memory leaks if a developer omits `ngOnDestroy`. Additionally, once a `Subscription` instance is unsubscribed, calling `.add()` on it again will immediately unsubscribe the new stream, preventing it from executing.

## 4. The Interview Strategy: Bridging Angular 14 to Angular 16+ (`takeUntilDestroyed`)

As a candidate with 5+ years of experience, interviewers will evaluate whether you are stuck in older paradigms or if you are keeping up with modern Angular.

**How to phrase this in an interview:**

> _"In our current Angular 14 codebase, we strictly use the `AsyncPipe` to let Angular manage subscriptions in the view layer. For TypeScript-side subscriptions, our architectural standard is the `takeUntil(this.destroy$)` pattern to ensure clean reactive disposal. However, I am fully aware that in Angular 16+, the framework introduced `takeUntilDestroyed()` via `@angular/core/rxjs-interop`. This injects `DestroyRef` to remove the `ngOnDestroy` boilerplate completely. When our team migrates, we intend to phase out the custom `destroy$` subject patterns in favor of this modern native operator."_

### What `takeUntilDestroyed` Looks Like (For your knowledge)

```typescript
// Angular 16+ code for interview context
import { Component, inject, DestroyRef } from '@angular/core';
import { takeUntilDestroyed } from '@angular/core/rxjs-interop';
import { interval } from 'rxjs';

@Component({ ... })
export class ModernComponent {
  // If declared in the constructor/field initializer, context is implied:
  private data\$ = interval(1000).pipe(takeUntilDestroyed());

  constructor() {
    this.data\$.subscribe();
  }
}
```

## 5. Comparative Quick Summary for Angular 14

| Strategy                       | Angular 14 Status    | Best Used For                                           | Memory Leak Risk         | Boilerplate |
| :----------------------------- | :------------------- | :------------------------------------------------------ | :----------------------- | :---------- |
| **AsyncPipe**                  | Native / Recommended | Binding data directly to HTML templates.                | None                     | Zero        |
| **takeUntil()**                | Native / Recommended | Managing complex RxJS streams in `.ts` files.           | Medium (Order dependent) | Medium      |
| **Subscription.unsubscribe()** | Native / Legacy      | Legacy code, native DOM listeners, non-Angular classes. | High (Easy to forget)    | High        |
| **takeUntilDestroyed()**       | **Unavailable**      | Modern Angular 16+ apps (Mention to show expertise).    | Low                      | Minimal     |
