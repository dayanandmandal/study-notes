# Why RxJS Feels Hard Initially

RxJS feels difficult at first because it introduces a different way of thinking about async programming.

Instead of writing:

```text
do this → then this → then this
```

(step-by-step imperative logic)

RxJS encourages:

```text
here is how values should flow through the system
```

(declarative stream-based logic)

---

# Imperative Style

You manually control every step:

```ts
input.addEventListener('input', event => {
  clearTimeout(timer);

  timer = setTimeout(() => {
    api.search(event.target.value)
      .then(result => {
        render(result);
      });
  }, 300);
});
```

You explicitly manage:
- events
- timers
- async calls
- cancellation
- rendering

This works, but becomes difficult as async complexity grows.

---

# Declarative RxJS Style

With RxJS:

```ts
fromEvent(input, 'input').pipe(
  debounceTime(300),
  map(event => event.target.value),
  distinctUntilChanged(),
  switchMap(value => api.search(value))
).subscribe(render);
```

Now you are describing:

```text
input stream
→ debounce values
→ transform values
→ ignore duplicates
→ cancel previous request
→ render latest response
```

Instead of manually controlling each step,
you define how data should flow.

---

# The Mental Shift

Imperative thinking:

```text
How do I execute these steps?
```

Reactive/RxJS thinking:

```text
How should values move through the system?
```

That shift takes time.

---

# Why RxJS Eventually Becomes Powerful

Once the mental model clicks, RxJS becomes extremely good for:

- async coordination
- cancellation
- debouncing
- event streams
- websocket streams
- combining async sources
- retries
- polling
- reactive UI state

---

# Important Realization

You do NOT need RxJS for everything.

Experienced Angular developers usually:
- use simple variables for simple state
- use RxJS where async streams actually exist

Good engineering is choosing the right abstraction level.
