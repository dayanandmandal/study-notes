# Cold vs Hot Observables

## Cold Observable

A new subscriber creates a new execution.

```ts
const obs$ = new Observable(observer => {
  console.log('Executing...');
  observer.next(Math.random());
});

obs$.subscribe(console.log);
obs$.subscribe(console.log);
```

Output:

```text
Executing...
0.123

Executing...
0.789
```

Rule:

```text
New Subscriber → New Execution
```

Examples:

* `http.get()`
* `of()`
* `from()`
* Most RxJS creation operators

---

## Hot Observable

Multiple subscribers share the same execution.

```ts
const subject = new Subject<number>();

subject.subscribe(v => console.log('A', v));
subject.subscribe(v => console.log('B', v));

subject.next(1);
```

Output:

```text
A 1
B 1
```

Rule:

```text
New Subscriber → Join Existing Execution
```

Examples:

* `Subject`
* `BehaviorSubject`
* `ReplaySubject`
* `fromEvent()`
* Angular Router events

---

# Why Subject Exists

Problem:

```ts
const data$ = http.get('/api');

data$.subscribe();
data$.subscribe();
```

Result:

```text
HTTP Request #1
HTTP Request #2
```

Solution:

```ts
const subject = new Subject();

data$.subscribe(subject);

subject.subscribe(A);
subject.subscribe(B);
```

Flow:

```text
Source
  ↓
Subject
 ↙   ↘
A     B
```

Benefit:

```text
One Execution → Many Subscribers
```

Subject provides manual multicasting.

---

# Why multicast() Existed

Before `share()`, RxJS provided:

```ts
source.pipe(multicast(subject))
```

Purpose:

```text
Convert a Cold Observable into a multicasted Observable.
```

Additional benefit:

```text
Subscribers can join first,
then source execution can be started via connect().
```

Concept:

```text
Subscribe Everyone
        ↓
connect()
        ↓
Source Starts
```

Modern RxJS generally uses `share()` instead.

---

# Why share() Exists

Problem:

```ts
const data$ = http.get('/api');

data$.subscribe();
data$.subscribe();
```

Result:

```text
2 HTTP Requests
```

Solution:

```ts
const data$ = http.get('/api').pipe(
  share()
);
```

Result:

```text
1 HTTP Request
2 Subscribers
```

Conceptually:

```text
Source
  ↓
Internal Subject
 ↙   ↘
A     B
```

Benefit:

```text
Automatic Multicasting
```

No manual Subject management required.

---

# Why shareReplay() Exists

Problem:

A late subscriber misses previous values.

```ts
const shared$ = source$.pipe(
  share()
);
```

```text
A subscribes
Value emitted
B subscribes
```

B misses the previous value.

Solution:

```ts
const shared$ = source$.pipe(
  shareReplay(1)
);
```

Now:

```text
A subscribes
Value emitted
B subscribes
```

B immediately receives the latest value.

Benefit:

```text
Shared Execution
+
Replay Previous Values
```

Common Angular use case:

```ts
user$ = this.http.get('/user').pipe(
  shareReplay(1)
);
```

Multiple components can use the same response without triggering multiple HTTP requests.

# Summary

```text
Cold Observable
=
New Subscriber → New Execution
```

```text
Hot Observable
=
New Subscriber → Existing Execution
```

```text
Subject
=
Manual Multicasting
```

```text
multicast()
=
Create Connectable Multicast Observable
```

```text
share()
=
Automatic Multicasting
```

```text
shareReplay()
=
Automatic Multicasting
+
Replay Previous Values
```

---

# Interview One-Liner

Cold Observables create a separate execution for each subscriber. Hot Observables share a single execution among multiple subscribers. Subjects enable manual multicasting, `share()` provides automatic multicasting, and `shareReplay()` additionally replays previous emissions to late subscribers.
